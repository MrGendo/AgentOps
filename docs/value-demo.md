# AgentOps 价值演示：同一批编程任务，两个模型的选型答案

- 日期：2026-10-26 · 数据集 swe-local v1（3 个真实代码修复任务，独立验收测试判定）
- 全链路真实执行：mini-SWE-agent 驱动 → 隔离 git 工作区 → 独立 pytest 验收 → 指标落库

## 一、模型对比（评测系统自动产出）

| 指标 | GLM-5.3（Coding Plan） | glm-4-flash（免费） |
|---|---|---|
| 任务完成率（验收通过口径） | **1.0（3/3）** | 0.3333（1/3） |
| 结果正确率 | **1.0** | 0.3333 |
| 逐任务结果 | 全部 SUCCEEDED | 2 失败 1 成功 |
| 任务耗时 | 140s, 55s, 101s | 17s, 12s, 36s |

**选型结论（平台用数据回答，不靠评测文章）**：免费的 flash 在严格输出格式下大量失败；
5.3 一次到位。若按"每次成功修复的有效成本"计算，Coding Plan 是正收益。

## 二、可靠性实录（平台接住的每一次真实故障）

| 事件 | 平台行为 | 裸跑脚本的下场 |
|---|---|---|
| 上游运行时缺 mcp 包 | AGENT_CRASHED 如实落库，工作区保留为证据 | 进程死，无痕迹 |
| litellm 不识别模型成本表 | 定位到上游开关，配置修复 | 报错弃疗 |
| flash 连续 3 次输出格式错误 | RepeatedFormatError → 独立验收判 FAILED，不采信任何自述 | "好像跑完了？" |
| GLM-5.3 修复 boundary_bug | 5 次模型调用 → 补丁 lo<=v<=hi → 独立验收 4/4 passed → SUCCEEDED | 无法验证 |

## 三、"Agent 报告成功" ≠ "真的修好了"

平台的核心价值之一：**验收测试由平台另起进程执行，Agent 的自述不作数**。
本次 flash 的失败样例中，Agent 未做任何有效修改——若没有独立验收，
"任务完成"与"什么都没发生"在界面上毫无区别。

## 四、一分钟现场演示脚本

1. `make demo` —— 运维诊断全链路（任务→Agent→工具→评测→诊断）
2. 控制台 → 任务 → 创建 `swe.fix`（boundary_bug 模板）→ 看隔离工作区里的真实修复
3. 控制台 → 评测 → 选数据集 swe-local → 看 GLM-5.3 vs flash 的版本对比视图
4. 点任一失败样例 → 下钻任务详情 → 诊断报告（故障码+证据引用）

> 数据库中的真实记录：evaluation_runs（glm-5.3 / glm-4-flash 两轮）、
> 每个样例的 tasks + agent_runs（补丁、验收输出、模型调用数）。
