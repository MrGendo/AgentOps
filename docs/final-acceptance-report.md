## 七、已知限制（如实清单）
1. 无用户认证/RBAC（需求允许 MVP 从简）；服务令牌为静态共享，服务化时应升级。
2. 浏览器自动化测试未包含（手动清单 + 同源实测代替）。
3. Python 进程内运行态（agent/评测）易失：重启即丢，Go 按可重试错误整体重发，任务不悬挂但运行历史在进程内。
4. 评测样例串行执行（并发位预留）；LLM 裁判仅留接口位。
5. 取消在步骤/工具边界生效，长步骤靠租约过期兜底。
6. 性能数据仅本机单次，未做容量规划。
7. 真实模型适配器未联调（无密钥环境；默认 Mock 全链路验收）。

## 八、服务化演进建议（对齐架构 §9 / 需求 §18）
按负载顺序拆分：Worker 独立扩容 → 工具网关独立（权限体系增长时）→ Agent Runtime 隔离模型资源 → 评测/诊断独立（批量不影响在线）→ 查询面分离。前提：保留 API 契约/任务 ID/事件结构与现有自动化测试；引入 MQ 前须补投递幂等/重放/死信设计，引入工作流引擎前先验证其是否解决真实痛点（§18）。
