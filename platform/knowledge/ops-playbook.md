# 运维诊断知识库（演示种子数据）

## 服务响应变慢排查
服务响应变慢的常见原因：慢查询激增、连接池耗尽、下游依赖超时、GC 停顿。第一步看 P99 延迟曲线是否与 QPS 同步上升，若不同步则优先排查下游依赖与锁等待。数据库层面用 pg_stat_statements 找出平均耗时最高的语句。

## 慢查询定位
慢查询通常伴随磁盘 IO 升高与缓冲命中率下降。检查执行计划是否全表扫描、索引是否失效、统计信息是否过期。应急措施：对查询加语句超时，避免拖垮连接池；再按执行计划补索引或改写查询。

## 内存泄漏特征
RSS 持续上升而请求量平稳、重启后恢复，是典型内存泄漏曲线。结合 runtime 指标区分堆增长与堆外（ mmap / cgo ）。先用 pprof 采样对比 24 小时前后的堆图，定位增长对象。

## CPU 飙高处理
CPU 飙高先区分用户态与内核态：用户态高多为热点代码或正则回溯，内核态高多为系统调用或缺页。配合火焰图定位；若与流量无关且伴随上下文切换骤增，检查是否陷入自旋锁或频繁的 futex 等待。

## 下游依赖超时
下游超时会通过重试放大为级联故障。核对客户端超时与重试配置：超时应小于上游容忍上限，重试须带退避与上限。结果未知的超时不能直接重试，应先查询下游状态确认是否已执行（幂等键 + 状态查询）。

## 磁盘 IO 打满
IO 打满常见于日志刷盘、排序溢出、快照备份。区分顺序写与随机写：随机读放大优先检查缓冲命中率与查询模式；顺序写检查日志级别与采样率。
